# concept.md（必ず書く：最新版）
#1.概要（Overview）（先頭固定）
- 作るもの（What）：Python製の最小DAG実行ライブラリ（Pyoco）
- 解決すること（Why）：小規模ワークフローを簡単に定義・実行し、手作業の手順を再現可能にする
- できること（主要機能の要約）：DAG定義、依存解決と実行、並列実行、タスク間データ受け渡し、コンソールでの実行トレース、LLM向け支援情報の生成（タスク一覧/詳細/flow.yamlガイド、format: prompt/json/md）
- 使いどころ（When/Where）：ローカル開発/小規模チームの単一マシン実行
- 成果物（Outputs）：タスクの戻り値、生成ファイル（任意）、実行結果のコンソール表示、LLM支援情報（prompt/json/md の文字列/ファイル）
- 前提（Assumptions）：外部DBやログ永続化は持たず、Pythonコードで完結する。LLM支援情報は文字列または指定ファイルに出力する。

#2.ユーザーの困りごと（Pain）
- 手順がコード化されておらず再現性が低い
- 小規模タスクなのに大型ワークフロー基盤は重すぎる
- 依存関係のある処理を手動で順序管理するのが面倒
- 並列化や成果物の受け渡しが煩雑
- 利用可能なタスク/入出力仕様が分散しており、LLMに正しく渡しづらい
- flow.yaml の書き方が属人的で、LLM支援の材料が不足する

#3.ターゲットと前提環境（詳細）
- ターゲット: 小規模開発チームの開発者
- 利用環境: ローカルPC（Windows/macOS/Linux想定）、Python実行環境、ネットワーク必須ではない
- 運用: 単一マシン内での実行、共有はリポジトリ/成果物ファイルで行う

#4.採用する技術スタック（採用理由つき）
- Python（純粋Pythonで実装・配布が容易、学習コストが低い）
- 標準ライブラリ中心（依存を最小化し軽量に保つ）

#5.機能一覧（Features）
| ID | 機能 | 解決するPain | 対応UC |
|---|---|---|---|
| F-1 | DAGのコード定義（タスク/依存の宣言） | 手順がコード化されていない | UC-1, UC-2 |
| F-2 | 依存解決と順序実行 | 手動の順序管理が面倒 | UC-1 |
| F-3 | 独立タスクの並列実行 | 並列化が煩雑 | UC-3 |
| F-4 | タスク間データ受け渡し | 成果物の受け渡しが煩雑 | UC-1, UC-4 |
| F-5 | 実行トレースのコンソール出力 | 実行状況が見えない | UC-1, UC-2, UC-3 |
| F-6 | 中断/エラー時の停止 | 例外時の扱いが不明確 | UC-2, UC-3 |
| F-7 | タスクメタ情報の収集と整理（フィルタ可） | タスク仕様が分散 | UC-5 |
| F-8 | LLM支援情報の生成（タスク一覧/詳細/flow.yamlガイド） | LLMへの組み込みが難しい | UC-5 |

#6.ユースケース（Use Cases）
| ID | 主体 | 目的 | 前提 | 主要手順（最小操作） | 成功条件 | 例外/制約 |
|---|---|---|---|---|---|---|
| UC-1 | 開発者 | 小規模ETL/前処理をDAGで実行 | Python環境がある | 1) タスクを定義 2) 依存を接続 3) 実行 | 依存順に正しく実行される | タスク失敗時は停止 |
| UC-2 | 開発者 | 手作業手順を再実行可能にする | ローカルで完結 | 1) 既存処理をタスク化 2) Flowに登録 3) 実行 | 同じ手順が再現できる | Ctrl+Cで中断可能 |
| UC-3 | 開発者 | 依存のない処理を並列化する | 単一マシン内で実行 | 1) 独立タスクを定義 2) 実行 | 並列で短時間実行 | CPU/IO制約に依存 |
| UC-4 | 開発者 | タスク成果物を次のタスクに渡す | 受け渡しはメモリ/ファイル | 1) 上流タスクが出力 2) 下流が参照 | 正しいデータが渡る | 大きなデータはパス渡し |
| UC-5 | 開発者 | LLM向け支援情報を取得する | config/プラグインが読み込める | 1) 出力種別/形式を指定 2) 任意でタスクをフィルタ 3) 支援情報を取得 | ①一覧②詳細③ガイドが得られる（name/origin/tag でフィルタ可能） | 必須メタ情報欠落は例外 |

#7.Goals（Goalのみ／ユースケース紐づけ必須）
- G-1: 小規模ワークフローを最小のコードで実行できる（対応：UC-1）
- G-2: 手順の再現性を高める（対応：UC-2）
- G-3: 独立タスクの並列実行を容易にする（対応：UC-3）
- G-4: タスク間データ受け渡しを簡単にする（対応：UC-4）
- G-5: LLM向け支援情報を正確に提供する（対応：UC-5）

#8.基本レイヤー構造（Layering）
| レイヤー | 役割 | 主な処理/データ流れ |
|---|---|---|
| プレゼンテーション層 | Python API/CLI | ユーザー定義のタスク/Flow入力 |
| アプリケーション層 | 実行制御 | 依存解決、実行順序、並列制御、支援情報生成 |
| ドメイン層 | DAGモデル | Flow/Task/RunContext/TaskRecord/TaskInfoの整合性 |
| インフラ層 | 実行基盤 | スレッド実行、ファイルI/O |

#9.主要データクラス（Key Data Classes / Entities）
| データクラス | 主要属性（不要属性なし） | 用途（対応UC/Feature） |
|---|---|---|
| Flow | name, tasks, _definition | DAG全体の定義（UC-1/F-1） |
| Task | func, inputs, outputs, dependencies | タスク処理と入力定義（UC-1/F-1） |
| RunContext | run_id, status, tasks, task_records | 実行の状態追跡（UC-2/F-5） |
| TaskRecord | state, duration_ms, error, output | タスク実行記録（UC-2/F-5） |
| Context | params, results, scratch, artifacts, env, artifact_dir | 実行時コンテキスト（artifactsは慣習的な入れ物）（UC-4/F-4） |
| TaskIO | name, type, required, constraints | タスク入出力の定義（UC-5/F-7） |
| TaskInfo | name, summary, inputs, outputs（必須）, origin, tags | タスクメタ情報（UC-5/F-7） |
| SupportInfo | kind, format(prompt/json/md), content, filters | 支援情報の出力（UC-5/F-8） |

#10.機能部品の実装順序（Implementation Order）
1. DAGモデル（Flow/Task）
2. 依存解決と順序実行
3. 並列実行
4. タスク間データ受け渡し（Context.artifacts）
5. コンソールトレースと中断処理
6. LLM支援情報の生成（タスク一覧/詳細/flow.yamlガイド）

#11.用語集（Glossary）
- DAG: 有向非巡回グラフ。タスクの依存関係を表す。
- Task: 1つの処理単位。
- Flow: タスク集合と依存関係のまとまり。
- RunContext: 実行単位。実行状態やIDを持つ。
- TaskRecord: タスクの実行状態/結果の記録。
- Artifact: タスク成果物の参照（Context.artifacts上の慣習的ラベル）。
- TaskInfo: タスクの説明情報（入出力や由来を含む）。
- SupportInfo: LLM向け支援情報の出力単位（一覧/詳細/ガイド）。
